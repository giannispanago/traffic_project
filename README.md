Traffic Video Analysis Project
Σκοπός του project

Ο στόχος του project είναι η ανάλυση βίντεο κυκλοφορίας με χρήση Python και YOLO, έτσι ώστε να γίνεται εντοπισμός και παρακολούθηση οχημάτων, καταγραφή διελεύσεων από γραμμές μέτρησης και παραγωγή στατιστικών αναφορών.

Η τελική κατεύθυνση του project είναι να τρέχει παράλληλα στο Azure, με χρήση Docker containers, ώστε το αρχικό βίντεο να χωρίζεται σε 2λεπτα clips, κάθε clip να επεξεργάζεται ανεξάρτητα, να παράγει τα δικά του αποτελέσματα και reports, και στο τέλος όλα τα επιμέρους outputs να γίνονται merge σε ένα ενιαίο τελικό αποτέλεσμα.

Τι έχει υλοποιηθεί μέχρι στιγμής

Μέχρι τώρα έχει γίνει η βασική τοπική υλοποίηση του pipeline.

1. Προεπεξεργασία / διαχωρισμός βίντεο

Το αρχικό βίντεο χωρίζεται σε μικρότερα clips διάρκειας 2 λεπτών.
Αυτό γίνεται ώστε το κάθε τμήμα να μπορεί αργότερα να επεξεργαστεί ανεξάρτητα και παράλληλα.

2. Επεξεργασία κάθε clip

Για κάθε clip εκτελείται επεξεργασία με τα κατάλληλα scripts, ώστε να:

γίνεται detection / tracking οχημάτων
υπολογίζονται διελεύσεις από συγκεκριμένες γραμμές
καταγράφονται στοιχεία όπως frame, χρόνος, direction, speed κλπ.
παράγεται αποτέλεσμα csv για το συγκεκριμένο clip
3. Παραγωγή reports

Από τα αποτελέσματα παράγονται reports / ερωτήματα στατιστικής ανάλυσης.
Μέχρι στιγμής στο project υπάρχουν τα παρακάτω outputs/reports:

q1_speed_each_vehicle.csv
q2_count_per_direction.csv
q3_speeding_by_direction.csv
q4_alerts_over_130.csv
q5_count_per_direction_per_5min...
q6_avg_speed_per_direction_per_...

Άρα η λογική είναι ότι από κάθε clip προκύπτουν τα αντίστοιχα δεδομένα και στη συνέχεια παράγονται τα 6 reports.

4. Merge αποτελεσμάτων

Υπάρχει ήδη λογική για merge των επιμέρους αποτελεσμάτων, ώστε τα αποτελέσματα από όλα τα clips να ενώνονται σε συνολικό αρχείο.

5. Βασική orchestration με main script

Αυτή τη στιγμή υπάρχει main λογική μέσω του run_all_clips.py, το οποίο:

βρίσκει όλα τα clips στον φάκελο output/clips
καλεί το process_clip.py για κάθε clip
δίνει output csv για κάθε clip
υπολογίζει το σωστό χρονικό offset (clip_offset_sec)
εκτελεί την επεξεργασία σειριακά, ένα clip τη φορά

Με άλλα λόγια, το pipeline υπάρχει, αλλά αυτή τη στιγμή τρέχει σειριακά και όχι παράλληλα.

Τρέχουσα κατάσταση του κώδικα

Αυτή τη στιγμή η main συνάρτηση καλεί τις υπόλοιπες υποσυναρτήσεις / scripts με τρόπο που επεξεργάζεται όλα τα clips που βρίσκονται μέσα στο directory.

Αυτό είναι χρήσιμο για τοπικό testing, αλλά δεν είναι η τελική μορφή που θέλουμε για Azure parallelization.

Ο λόγος είναι ότι στο Azure δεν θέλουμε κάθε container να επεξεργάζεται όλα τα clips.
Θέλουμε κάθε container / job να αναλαμβάνει συγκεκριμένο clip ή συγκεκριμένο subset clips.

Τι θέλουμε να γίνει στη συνέχεια

Το επόμενο βασικό βήμα είναι η μετάβαση από το τοπικό σειριακό pipeline σε παράλληλη εκτέλεση στο Azure.

Στόχος

Να γίνει η αρχιτεκτονική ως εξής:

Το αρχικό βίντεο αποθηκεύεται στο Azure Blob Storage.
Γίνεται preprocessing και χωρισμός σε clips των 2 λεπτών.
Τα clips αποθηκεύονται επίσης στο storage.
Δημιουργούνται πολλαπλά Docker containers / Azure jobs.
Κάθε container επεξεργάζεται ένα συγκεκριμένο clip ή προκαθορισμένο σύνολο clips.
Για κάθε clip παράγονται:
το επιμέρους result csv
τα αντίστοιχα 6 reports
Στο τέλος γίνεται merge:
των επιμέρους result csv
και, όπου χρειάζεται, σύνθεση / merge των reports σε συνολικό τελικό output
Σημαντική αλλαγή που πρέπει να γίνει στον κώδικα

Αυτό είναι ίσως το πιο σημαντικό σημείο για τη συνέχεια:

Το run_all_clips.py δεν πρέπει τελικά να διαβάζει πάντα όλα τα clips από τον φάκελο και να τα εκτελεί όλα μαζί.

Αντί γι’ αυτό, πρέπει να αλλάξει ώστε:

να δέχεται ως είσοδο ποιο clip πρέπει να επεξεργαστεί
ή να δέχεται λίστα συγκεκριμένων clips
και να καλεί τις υποσυναρτήσεις μόνο για αυτά
Δηλαδή, η λογική πρέπει να γίνει κάπως έτσι:
container 1 → επεξεργασία clip_000.mp4
container 2 → επεξεργασία clip_001.mp4
container 3 → επεξεργασία clip_002.mp4
κ.ο.κ.

Έτσι επιτυγχάνεται πραγματικό parallel processing.

Πρακτικά

Η main συνάρτηση πρέπει να προσαρμοστεί ώστε να μπορεί να παίρνει arguments, για παράδειγμα:

input clip path
output path
clip offset
ίσως job/container id

Άρα η εκτέλεση δεν θα βασίζεται μόνο στο “βρες όλα τα clips στον φάκελο”, αλλά στο “τρέξε αυτό το συγκεκριμένο clip που σου ανατέθηκε”.

Azure κατεύθυνση

Μέχρι στιγμής έχει γίνει η αρχική οργάνωση στο Azure περιβάλλον και υπάρχει resource group / storage account για το project.

Η λογική που θέλουμε να ακολουθηθεί είναι:

Storage Account / Blob Storage για:
raw video
clips
per-clip results
per-clip reports
merged final outputs
Docker containers για το runtime περιβάλλον του project, ώστε να υπάρχει σταθερό και επαναλήψιμο execution environment
Azure compute / jobs / containers ώστε να εκτελούνται πολλά clips ταυτόχρονα
